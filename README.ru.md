# dsh-ssh-mcp

Постоянные SSH-сессии для [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)
в виде MCP-инструментов. Агент открывает одно подключение на хост и работает в
нём, а не авторизуется заново на каждую команду.

Автоматизация SSH обычно ломается в трёх местах, и плагин построен вокруг них:

- **Повторная авторизация на каждой команде.** Открывать новый `ssh` под каждую
  команду — медленно и шумно. `open` поднимает одну постоянную сессию, `exec`
  переиспользует её и сохраняет рабочий каталог и переменные окружения.
- **fail2ban.** Цикл ретраев против защищённого хоста отправляет адрес в бан на
  часы. Плагин считает неудачные попытки по `host:port` и останавливается после
  одного ретрая.
- **sudo под root.** Во многих минимальных образах sudo нет вовсе, а для
  root-логина он ломает валидные команды. Плагин определяет `uid 0` и запрещает
  sudo в root-сессии.

## Возможности

- Одна постоянная сессия `ssh -T` на хост: у каждой команды свой код возврата и
  свой вывод, обрамлённый маркером.
- Профили доступа в JSON: адрес, нестандартный порт, пользователь, файл ключа,
  политика fail2ban.
- Авторизация через ssh-agent или явный ключ; парольная авторизация намеренно не
  поддерживается — у сервера нет терминала, отвечать на приглашение некому.
- Определение root: `open` возвращает `is_root`, а `exec` с `sudo` в root-сессии
  отклоняется.
- Подтверждение для `sudo` и разрушительных команд (`rm -rf /`, `mkfs`,
  `dd of=/dev/...`, `reboot`, удаление пакетов, `DROP DATABASE` и т. п.).
- Классификация ошибок с подсказкой: `auth_failed`, `connection_refused`,
  `network_unreachable`, `dns_failed`, `host_key_rejected`, `connect_halted`,
  а также `local_path_missing`, `path_missing`, `spawn_failed`,
  `transfer_timeout`.
- `put` / `get` — передача файлов через scp; локальный путь отсчитывается от
  workspace.
- Правила безопасности приходят в системный промпт вместе с MCP-сервером;
  дополнительно можно поставить skill с полным playbook.

## Требования

- DeepSeek Harness с поддержкой MCP-клиента (`@deepseek-ai/dsh-mcp-client`).
- Клиент OpenSSH (`ssh`, `scp`) в `PATH`. В Windows 10/11 включается через
  `Add-WindowsCapability -Online -Name OpenSSH.Client~~~~0.0.1.0`.
- Удалённый хост с POSIX `sh`. Windows-хосты не поддерживаются.
- Системный Node.js не нужен: MCP-сервер работает на том же бинарнике, что и
  Harness, переключённом в режим Node.

## Установка

### Plugin Manager (Desktop)

Settings → Plugins → установка по спецификации пакета:

```
github:extreme-russian-dsh-fandom/dsh-ssh-mcp
```

### Командная строка

```sh
dsh plugin --profile <profile> add github:extreme-russian-dsh-fandom/dsh-ssh-mcp
```

Для воспроизводимости закрепите ревизию:

```sh
dsh plugin --profile <profile> add github:extreme-russian-dsh-fandom/dsh-ssh-mcp#v1.0.0
```

`github:` — это сокращение pnpm, а не схема DSH: `dsh plugin` передаёт аргумент в
pnpm, а Plugin Manager предварительно проверяет репозиторий через `git ls-remote`.

После активации инструменты появляются как `mcp__ssh__<tool>`.

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| `mcp__ssh__profiles` | Список профилей: хост, порт, пользователь, способ входа, политика fail2ban. Секреты не возвращаются. Вызывать первым. |
| `mcp__ssh__open` | Открыть постоянную сессию. Возвращает `session_id`, `is_root`, ОС и оболочку. |
| `mcp__ssh__exec` | Выполнить команду в сессии; вернуть код возврата, stdout и stderr. Необязательные `sudo` и `confirmed`. |
| `mcp__ssh__sessions` | Список открытых сессий: профиль, пользователь, root, возраст. |
| `mcp__ssh__close` | Закрыть сессию и освободить соединение. |
| `mcp__ssh__put` | Скопировать локальный файл или каталог на хост через scp. |
| `mcp__ssh__get` | Скопировать удалённый файл или каталог в workspace через scp. |

`put` и `get` считают относительный `local_path` от рабочего каталога сервера
(workspace на момент запуска), а не от рабочего каталога удалённой сессии.
Каталог назначения должен существовать; scp не раскрывает ни `~`, ни переменные
оболочки, поэтому при сомнениях передавайте абсолютный путь.

## Файл доступов

Сервер читает `~/.dsh/ssh-credentials.json` (можно переопределить через
`--credentials`, `SSH_MCP_CREDENTIALS` или `ssh-credentials.json` в рабочем
каталоге). Файл создаёт пользователь, плагин его никогда не пишет.

```json
{
  "defaults": {
    "port": 22,
    "user": "root",
    "fail2ban": "unknown",
    "strictHostKey": "accept-new",
    "connectTimeoutMs": 15000
  },
  "hosts": {
    "prod-web": {
      "host": "203.0.113.10",
      "port": 22222,
      "user": "deploy",
      "auth": "agent",
      "fail2ban": "present",
      "description": "sshd на нестандартном порту, ключ в агенте"
    },
    "prod-db": {
      "host": "db.internal.example",
      "port": 4242,
      "user": "root",
      "auth": "key",
      "identityFile": "C:\\Users\\me\\.ssh\\id_ed25519",
      "fail2ban": "present",
      "sudo": "none"
    }
  }
}
```

Полный пример — в
[`examples/ssh-credentials.example.json`](examples/ssh-credentials.example.json).

| Поле | Значения | Смысл |
| --- | --- | --- |
| `host` | строка | Адрес или DNS-имя. Обязательно. |
| `port` | 1–65535 | Порт sshd; высокие порты для укреплённых хостов — норма. |
| `user` | строка | Пользователь входа. По умолчанию из блока `defaults`. |
| `auth` | `auto`, `agent`, `key` | `auto` использует `identityFile`, если он задан, иначе агент/ключи по умолчанию. |
| `identityFile` | путь | Приватный ключ для `auth: key`. |
| `fail2ban` | `unknown`, `present`, `absent` | Бюджет попыток: 2 по умолчанию, 3 только при явном `absent`. |
| `sudo` | `nopasswd`, `none` | Ожидается ли на хосте sudo без пароля. |
| `strictHostKey` | `accept-new`, `yes`, `no` | `accept-new` доверяет хосту при первом контакте; `yes` требует known_hosts. |
| `connectTimeoutMs` | 1000–120000 | Таймаут TCP/авторизации для одной попытки. |

Держите файл закрытым (`chmod 600` на POSIX). Его нельзя коммитить; в
`.gitignore` репозитория он уже исключён.

Парольная авторизация не поддерживается: у MCP-сервера нет терминала, и `ssh` не
может ответить на приглашение ввода пароля. Установите публичный ключ на
удалённый хост или используйте ssh-agent. Профиль с `passwordFile` намеренно
падает с `password_auth_unsupported`.

## Модель безопасности

| Правило | Поведение |
| --- | --- |
| Учёт fail2ban | Неудачные подключения считаются по `host:port`. Когда бюджет исчерпан, хост блокируется до конца жизни процесса, а инструмент велит агенту остановиться и обратиться к пользователю. Чисто локальные сбои (нет локального пути, не установлен клиент OpenSSH) не считаются: до хоста дело не дошло. |
| Root-сессии | `open` сообщает `is_root`. `exec` с `sudo: true` в root-сессии возвращает `sudo_not_applicable`; команду нужно повторить без sudo. |
| Подтверждения | `sudo` и разрушительные команды требуют `confirmed: true`, который агент выставляет только после явного согласия пользователя. |
| Секреты | Модель видит только путь к файлу доступов; ключи и пароли в контекст не попадают. |

Эти правила встроены в инструкции MCP-сервера и попадают в системный промпт даже
без установленного skill.

## Skill (необязательно)

В комплекте есть готовый playbook:
[`skill/remote-ssh/SKILL.md`](skill/remote-ssh/SKILL.md). Скопируйте его в
каталог скиллов, чтобы получить полный гид по диагностике:

```sh
mkdir -p ~/.dsh/skills/remote-ssh
cp skill/remote-ssh/SKILL.md ~/.dsh/skills/remote-ssh/
```

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `DSH_SSH_MCP_SERVER` | Абсолютный путь к `server/index.mjs`, если пакет лежит не в `<cwd>/node_modules/dsh-ssh-mcp`. |
| `DSH_SSH_MCP_NODE` | Бинарник для запуска сервера. По умолчанию — бинарник запущенного Harness. |
| `DSH_SSH_MCP_TIMEOUT_MS` | Таймаут одного вызова MCP. По умолчанию 600000. |
| `SSH_MCP_CREDENTIALS` | Альтернативный путь к файлу доступов. |

## Диагностика

| Симптом | Причина и решение |
| --- | --- |
| Нет инструментов `mcp__ssh__*` | MCP-сервер не стартовал. Проверьте, что `ssh.exe`/`ssh` в `PATH`, и имя хоста. |
| `credential_missing` | Создайте `~/.dsh/ssh-credentials.json`; `mcp__ssh__profiles` вернёт шаблон. |
| `auth_failed` | Хост не принимает ключ. Добавьте публичный ключ в `authorized_keys`; плагин разрешает только один ретрай. |
| `connect_halted` | Бюджет попыток для хоста исчерпан. Почините доступ и перезапустите процесс Harness. В подсказке указан код сбоя, который израсходовал бюджет. |
| `local_path_missing`, `path_missing` | На одной из сторон `put`/`get` нет такого пути; ничего не скопировано, попытка не списана. Проверьте оба пути (относительный локальный путь считается от workspace). |
| `spawn_failed` | Не удалось запустить `ssh` или `scp`. Установите клиент OpenSSH или добавьте его в `PATH`; локальный сбой бюджет не тратит. |
| `sudo_requires_password` | Не настроен sudo без пароля. Добавьте правило `NOPASSWD` или выполните команду вручную. |
| `host_key_rejected` | Ключ хоста изменился. Проверьте хост и обновите `known_hosts`; плагин никогда не ослабляет проверку ключей. |

## Удаление

```sh
dsh plugin --profile <profile> remove dsh-ssh-mcp
```
