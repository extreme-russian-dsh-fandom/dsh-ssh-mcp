# Удалённое администрирование по SSH

Инструменты: `mcp__ssh__profiles`, `open`, `exec`, `sessions`, `close`, `put`, `get`.
Корневые правила (fail2ban, root/sudo, подтверждения) приходят от самого сервера
в системном промпте — здесь подробный порядок действий.

## Порядок работы

1. **`profiles`** — узнать доступные профили. Если список пуст, не подключаться:
   попросить пользователя заполнить `ssh-credentials.json` (шаблон вернёт сам
   инструмент). Никогда не просить пароль или приватный ключ в чат.
2. **`open`** — один раз на сервер. Запомнить `session_id`, `is_root`, `os`.
3. **`exec`** — сколько нужно команд в этой же сессии. Не открывать новую сессию
   на каждую команду: это лишние авторизации и риск для fail2ban.
4. **`close`** — когда работа закончена.

Сессия живёт в процессе MCP-сервера. Если DSH перезапустили или упал, сервер
завершится вместе с ней; после перезапуска сессии нужно открывать заново.

## Авторизация

По умолчанию считается, что удалённый сервер уже знает наш `id_ed25519` и
ssh-agent держит ключ. Если `open` вернул `auth_failed`:

- один повтор допустим (это и есть «одна повторная попытка»);
- если и он не прошёл — **остановиться** и попросить пользователя проверить
  `authorized_keys` на сервере, порт и `sshd_config`;
- не перебирать других пользователей, ключи и порты: на сервере может быть
  fail2ban, и перебор отправит нас в бан на часы.

Парольная авторизация не поддерживается: у MCP-сервера нет терминала, ssh не
может ответить на приглашение ввода пароля. Профиль с `passwordFile` вернёт
`password_auth_unsupported` — это ожидаемо, нужно ставить ключ.

## fail2ban

- Бюджет попыток на хост: 2 (одна основная + один повтор). Если в профиле
  явно указано `"fail2ban": "absent"` — 3.
- После исчерпания `open` возвращает `connect_halted`, и сервер больше не
  пытается подключиться к этому хосту до перезапуска процесса.
- При `connect_halted` запрещено обходить ограничение через `put`/`get` или
  другой профиль с тем же адресом: сначала пользователь чинит доступ, потом
  работа продолжается.
- Ошибки различаются по коду: `auth_failed`, `connection_refused`,
  `network_unreachable`, `timeout`, `dns_failed`, `host_key_rejected`. Для
  каждого в ответе есть подсказка, что именно проверить.

## Root и sudo

- `open` возвращает `is_root`. Если `true` — **sudo не использовать вообще**:
  на многих системах его нет, и валидная команда упадёт с «unknown command».
  Привилегированные команды выполняются напрямую.
- Если `is_root: false` и нужны права root — сначала спросить пользователя,
  затем вызвать `exec` с `sudo: true, confirmed: true`.
- `sudo` работает только при настроенном passwordless sudo (`NOPASSWD`).
  Ответ `sudo_requires_password` означает, что нужно либо настроить NOPASSWD,
  либо выполнить команду вручную; пароль не запрашивать.
- Профиль с `"sudo": "none"` означает, что на хосте sudo не используется.

## Подтверждения

Перед `sudo` и перед разрушительными командами (`rm -rf` на корень или home,
`mkfs`, `dd` на устройство, `reboot`, удаление пакетов, `DROP DATABASE`,
`kubectl delete`, `terraform destroy`, force-push) инструмент вернёт
`confirmation_required`. Нужно:

1. показать пользователю точную команду и спросить разрешение;
2. только после явного «да» повторить вызов с `confirmed: true`.

Выставлять `confirmed` самостоятельно нельзя.

## Типичные сбои

| Код | Что делать |
|---|---|
| `credentials_missing` / `credentials_invalid` | Попросить пользователя создать или исправить файл по шаблону из ответа |
| `unknown_profile` | Сверить имя с `profiles`; не угадывать |
| `auth_failed` | Один повтор, затем остановка и просьба к пользователю |
| `connection_refused` | Проверить порт в профиле: sshd мог быть перенесён на высокий порт |
| `network_unreachable`, `timeout` | Проверить адрес, firewall, VPN; не долбить повторно |
| `host_key_rejected` | Остановиться: ключ хоста изменился, это решает пользователь |
| `session_dead` | Сессия закрыта (обрыв, таймаут команды) — открыть заново |
| `sudo_not_applicable` | Сессия под root: повторить команду без sudo |
| `sudo_requires_password` | Нужен NOPASSWD или ручное выполнение |

## Гигиена вывода

Вывод команд обрезается с явным маркером. Если нужен большой файл или лог,
не тянуть его целиком через `exec`: использовать `head`/`tail`/`grep` на
удалённой стороне либо `get`, чтобы забрать файл в workspace.
